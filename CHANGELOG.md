# Changelog

## 0.3.1 — 2026-09-09

**Atom labels in the sketcher no longer have bonds drawn through them.**

JSME sizes the white rectangle that masks the bond behind each atom label from
the on-screen width of the label text, which it measures with a probe element
appended to `<body>`. Our page made `<body>` a flex container, that probe
returned a width JSME rejected, and JSME fell back to a default string width —
so a multi-character label got a mask about a third of a character wide.

Measured against an otherwise identical page carrying none of our CSS:

| label | shipped in 0.3.0 | correct |
|---|---|---|
| `N`   | 420 | 420 |
| `OH`  | 150 | 720 |
| `HO`  | 150 | 720 |
| `NH2` | 150 | 930 |

Single letters were always correct, because JSME takes those from built-in
metrics — which is what made this look like a font problem rather than a layout
one. Visibly, a bond ran through the `N` of `NH2` and an `O` looked detached
from the carbon it was bonded to.

The page's flex column now lives on a `.shell` wrapper and `<body>` is a plain
block. Nothing else changed: every laid-out box is identical to 0.3.0, and a
pixel diff of the full page confirms every changed pixel falls inside the
editor's drawing area. A test guards it, since nothing throws when it breaks.

Also in this release:

- `ligand3d version` reported `0.1.0` while the package was `0.3.0`, so every
  structure written since then carries `Generated by ligand3d 0.1.0` in its
  header. The two are now equal and a test keeps them that way.
- The `VERSION` file installed alongside the containers said `--slurm` could not
  run from one. It can, and has been able to since the launcher started binding
  sbatch, `/etc/slurm` and munge's socket.
